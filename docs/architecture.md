# Flow Pilot 架构

本文维护职责边界、关键约束和实施顺序。任务服务与 AI 执行闭环为待实现方案；当前能力见 [README](../README.md)，产品与开发约定见 [AGENTS.md](../AGENTS.md)。

## 职责边界

| 模块               | 职责                                                                           |
| ------------------ | ------------------------------------------------------------------------------ |
| 客户端             | 输入目标、展示网页与活动、提供任务控制和用户接管；发送命令并读取服务状态与事件 |
| 任务服务           | 唯一写入正式任务与运行状态，负责校验、调度、协调 AI 与执行器、持久化结果       |
| AI 决策模块        | 理解目标和页面，提出结构化动作、澄清或验证建议，以及用户可见摘要               |
| 网页执行适配器     | 管理网页会话、采集观察、执行服务派发的操作，返回真实反馈与证据                 |
| 共享契约与领域规则 | 定义跨客户端契约和纯业务规则，不依赖 Electron、DOM、浏览器存储或模型 SDK       |

这些是代码职责边界，初期按实际需要组织模块与进程。模型调用与任务协调位于服务侧，浏览器与模型 SDK 对象留在对应适配器内部。正式任务契约在服务落地时定义，当前 demo 类型继续用于独立预览。

## 执行闭环

服务区分任务、运行和操作：任务保存长期目标、目标版本与定时；运行保存本轮触发来源、状态与检查点；操作与事件保存实际结果和历史。

1. 客户端提交命令，服务校验并保存目标版本与活动事件。
2. 执行器提供当前页面观察，包括页面、观察标识和可操作元素。
3. AI 返回结构化建议；服务校验参数、目标版本、观察有效性与运行状态。
4. 服务分配操作 ID、记录待执行操作，再交给执行器；初期每轮串行执行。
5. 执行器返回成功、失败或结果不确定，以及页面证据；服务保存结果，向客户端发布状态与事件。
6. 根据实际结果重新观察，继续操作、验证目标、等待用户或结束本轮。

AI 不直接写入任务状态或改变定时。工具执行成功、目标结果确认和运行完成需要分别判断；语义性目标可以由 AI 或用户依据证据判断，服务保存证据与判断来源。网页内容作为任务数据处理，不能改变工具权限和任务控制规则。

## 执行约束

任务控制的产品语义以 [项目约定](../AGENTS.md#当前桌面客户端) 为准，服务保证：

- 明确的暂停、终止等命令直接生效，不等待模型回复；停止派发后续操作，并核对在途操作已发生的结果。
- 目标修改后拒绝旧版本的模型建议；导航、页面变化或用户接管导致元素引用失效时重新观察。登录或接管期间暂停自动操作，用户交还后再继续。
- 命令通过 ID 去重；网页操作不假定幂等。结果未知或服务重启后，先核对未完成操作，尤其是保存、发送和发布，避免盲目重试。
- 不合法或不明确的定时设置不能退化成立即执行，应返回错误或澄清请求。
- 服务持久化活动事件，分配运行内序号并记录时间；客户端按游标恢复，展示用户修正、执行、AI 摘要、工具和 Skill 使用。

## 实现选择

按项目约定先自研最小执行器与 AI 循环。home 上的 HedgeDoc 已由 Electron 的 [WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view) 承载。网页与浮窗使用独立视图，避免原生网页覆盖 HTML 浮窗；网页采用独立的内存 session，不接收客户端 preload。请求与导航限制在 HedgeDoc 测试服务，同源新窗口在现有视图中打开，以便保留可见页面和任务浮窗。离开测试场景时隐藏视图，窗口关闭时释放；客户端只保证当前窗口会话内的页面状态保留，文档持久化由独立的 HedgeDoc 服务负责。

后续通过主进程原生接口与 [CDP](https://www.electronjs.org/docs/latest/api/debugger) 验证控制能力。按场景实现所需的观察、导航、点击、填写、滚动、等待和截图，并提供超时与失败反馈。网页宿主的连接用于客户端布局和可见状态，不是正式任务服务契约。

保持执行适配边界，遇到具体瓶颈再评估开源库能减少的工作量，以及体积、运行资源、版本兼容和任务控制适配成本。模型供应商、通信协议、持久化实现和后台生命周期在相应阶段验证后确定。

## 实施顺序

以一个前端可操作的场景为一次交付，人工验收通过后再进入下一步，所需服务与契约随场景逐步补齐。保留独立 demo 预览。当前功能的操作与通过条件集中维护在 [README 人工验收](../README.md#人工验收)，环境入口见 [外部验收环境](../README.md#外部验收环境)。

下一步为单个填写动作。以下步骤继续使用 HedgeDoc 匿名文档，每步操作由界面触发，结果可见。

| 步骤         | 前端操作                                           | 通过条件                                                                 |
| ------------ | -------------------------------------------------- | ------------------------------------------------------------------------ |
| 单个填写动作 | 在可编辑访客文档中触发一次固定内容修改             | 仅指定内容发生变化；浮窗展示真实执行结果，失败不会显示成功               |
| 保存与验证   | 修改后按应用实际保存机制读取反馈，重新打开同一文档 | 服务端内容与修改一致；保留验证证据后确认完成                             |
| 暂停与继续   | 发起串行固定动作，在执行中暂停，再继续             | 暂停后不派发新操作，继续从当前检查点推进；已完成动作与历史保留           |
| 终止与新一轮 | 执行中终止本轮，再发起新一轮                       | 本轮不再派发新操作，在途结果被核对；历史保留，新一轮独立开始             |
| 修改目标     | 执行中修正目标并重新规划                           | 后续操作采用新目标，拒绝迟到的旧建议；目标修正与旧事件保留在同一活动记录 |

随后逐项验证正式服务持久化、命令去重、客户端刷新与重连、失败和不确定结果；重启后的在途操作先核对再继续。其他平台场景再验证登录态、用户接管、所需富文本与 iframe、弹窗和导航。最后接入 AI，跑通一个有完成证据的真实任务。

单场景验证后，再增加保存流程与服务定时：明确流程参数、页面条件与版本，条件变化时由 AI 调整；验证错过与重叠触发、本轮与定时分别控制。关闭窗口后执行须验证服务与浏览器宿主的生命周期，完成后才能更新产品说明。其他平台与客户端复用已验证的边界，按实际需要扩展。
